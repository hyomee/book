# 소프트웨어설계

## 시스템 설계란?

**소프트웨어 시스템:** 단순한 코드의 집합을 넘어, 확장성, 유지보수성, 그리고 비즈니스 가치를 극대화하기 위해 여러 계층과 기술이 유기적으로 결합된 복잡한 아키텍처이다.

**소프트웨어 애플리케이션:** 복잡한 컴퓨터 기술을 추상화하여 "사용자가 원하는 실제적인 일(Task)을 해낼 수 있게 해주는 가장 최전선의 소프트웨어"라고 정의할 수 있다.

**분산 소프트웨어 시스템**: 물리적으로 분산되어 있는 여러 대의 독립적인 컴퓨터(노드)들이 네트워크를 통해 연결되어, 사용자에게는 마치 '하나의 단일하고 통합된 시스템'처럼 보이게 작동하는 시스템을 의미한다.

**1. 분산 시스템의 핵심 특징**

* **동시성 (Concurrency)**: 여러 노드나 마이크로서비스가 각자의 작업을 동시에 병렬로 처리하여 전체적인 처리량을 극대화한다.
* **단일 전역 시계의 부재 (No Global Clock)**: 노드들이 물리적으로 떨어져 있기 때문에 완벽하게 동일한 시간을 공유하기 어려우므로 이벤트의 선후 관계를 맞추고 동기화하기 위한 복잡한 메커니즘이 필요하다.
* **독립적인 장애 및 내결함성 (Fault Tolerance)**: 특정 노드, 데이터베이스, 혹은 네트워크의 일부가 고장 나더라도 시스템 전체가 멈추지 않고 정상적으로 서비스를 제공하도록 설계한다.

**2. 왜 분산 시스템을 구축하는가? (장점)**

* **무한한 수평 확장성 (Scale-out)**: 트래픽이 급증할 때, 단일 서버의 하드웨어 성능을 높이는 수직 확장(Scale-up)은 물리적/비용적 한계가 있으므로.분산 시스템은 K8s(Kubernetes) 환경처럼 새로운 컨테이너나 워커 노드를 동적으로 추가하여 트래픽을 유연하게 소화할 수 있다.
* **고가용성 (High Availability)**: AWS, GCP, Azure, 그리고 온프레미스 환경에 걸쳐 하이브리드로 시스템을 분산 배치하면, 한 데이터센터에 장애가 발생해도 무중단 서비스를 유지할 수 있다.
* **낮은 지연 시간 (Low Latency)**: 사용자와 물리적으로 가까운 엣지(Edge) 서버나 지역별 분산 노드에서 데이터를 처리하여 응답 속도를 비약적으로 높인다.

**3. 대표적인 적용 사례**

* **마이크로서비스 아키텍처 (MSA):** 웹 애플리케이션을 결제, 유저 관리, 알림 등 도메인 주도 설계(DDD) 기반의 독립된 서비스로 쪼개어 개발하고 배포한다.
* **다중 AI 에이전트 워크플로우**: 여러 개의 독립적인 AI 에이전트들이 각자의 역할(예: 코드 분석, UI 생성, 센서 데이터 수집)을 수행하며, 메시지 브로커를 통해 비동기적으로 소통하고 결과를 조율하는 지능형 파이프라인 역시 고도의 분산 시스템이다.
* **분산 데이터베이스**: PostgreSQL 클러스터 기반의 샤딩(Sharding)이나 실시간 로그 분석을 위한 분산 스토리지.

**4. 설계 시 마주하는 기술적 난제 (Trade-offs)**

시스템을 쪼개고 분산시킬수록 구조적 복잡도는 기하급수적으로 상승한다.

* **네트워크의 불확실성:** 노드 간 통신은 언제든 끊기거나 지연될 수 있으므로 재시도(Retry) 로직이나 장애가 전파되는 것을 막는 회로 차단기(Circuit Breaker) 패턴 적용이 필수적이다.
* **데이터 정합성 (Consistency):** 이른바 CAP 정리(일관성, 가용성, 파티션 감내성 중 두 가지만 취할 수 있음)에 따라, 분산된 노드 간에 데이터 상태를 완벽하게 일치시킬 것인지, 아니면 약간의 지연을 허용하는 최종적 일관성(Eventual Consistency)을 취할 것인지 타협해야 한다.
* **가시성(Observability) 확보의 어려움:** 하나의 사용자 요청이 수많은 계층과 노드를 거치기 때문에, 병목 구간을 찾기 위해서는 Prometheus, 로그 집계, 분산 트레이싱 등을 결합한 고도화된 모니터링 환경이 요구된다.
